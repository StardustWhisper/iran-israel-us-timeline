# 2026-03-18 — RSS 抓取 → 主题评分 → 自动写稿 → 配图 → 推公众号草稿箱

## 主线流程（当前稳定版）

目标：把多源 RSS / 博客更新自动转成“可直接发布到微信公众号草稿箱”的文章草稿。

### 1. RSS 抓取
数据源通过 blogwatcher / RSS 聚合后落地到 `rss/` 与 `rss/_tmp/`。
当前来源包括：
- 36kr-tech
- aws-news
- cloudflare
- github-blog
- github-changelog
- github-search
- hackernews
- infoq
- kubernetes
- microsoft-research
- openai-news
- v2ex-latest

相关脚本：
- `scripts/rss_radar_fetch.py`：把 RSS / blogwatcher 输出整理成结构化 JSON
- `scripts/rss_nightly.sh`：夜间 scan + 聚合 + 产出候选数据

核心产物：
- `rss/brief.json`
- 兼容旧文件：`rss/36kr-tech-brief.json`

### 2. 主题评分 / 排序
通过 `scripts/rss_radar_select_and_brief.py` 对候选条目做启发式评分，生成：
- `top`：最高分主题
- `top10`：前十候选
- `hugoBrief`：给写稿 agent 的写作角度、结构、约束

当前链路中，后续自动出稿默认读取 `rss/brief.json` 的 `top.title` 和 `top.url`。

### 3. 选取最高评分主题
早晨流程入口：`scripts/rss_morning_to_drafts.sh`

逻辑：
- 优先读 `rss/brief.json`
- 若不存在则回退到 `rss/36kr-tech-brief.json`
- 从中取出最高分主题标题与原始链接
- 作为当天自动出稿输入

### 4. 生成文章
`scripts/rss_morning_to_drafts.sh` 会调用：
- `scripts/openclaw_cli.sh agent --agent hugo ...`

让 HUGO 基于：
- 最高分主题标题
- 原始参考 URL（作为事实边界）

生成公众号文章 Markdown。

写作要求大致包括：
- 科技科普向
- 结构化（抓人开头 / 发生了什么 / 核心机制 / 常见误区 / 结论）
- 1800–2400 字
- 不编造来源没有明确支持的具体数字
- 附带封面图 prompt 备选

中间产物：
- `article_raw.md`

### 5. 生成插图 / 封面图
同一流程内调用图像脚本：
- `$HOME/.openclaw/workspace-dali/scripts/grok2api_image.sh generate`

当前用途：生成公众号封面图。

硬约束：
- 封面图必须无文字
- prompt 显式强调：
  - `no text`
  - `no letters`
  - `no numbers`
  - `no signage`
  - `no logos`
  - `no UI`

生成后再用 ffmpeg 裁切成公众号适配尺寸：
- 原始：`cover_src.png`
- 最终：`cover.jpg`
- 尺寸：`1080x864`

### 6. 包装为可发布 Markdown
自动给文章补 frontmatter：

```yaml
---
title: 文章标题
cover: ./cover.jpg
---
```

最终发布文件：
- `article.md`

### 7. 发布到微信公众号草稿箱
调用：
- `skills/wechat-publisher/scripts/publish.sh`

底层基于 wenyan-cli，把 `article.md` 推送到微信公众号草稿箱。

本次使用的发布参数：
- 主题：`lapis`
- 代码高亮：`solarized-light`

成功后会返回 Media ID，并可在微信公众号后台草稿箱查看。
